# Golden-эталоны поведения numerical-core 0.1.0

Назначение: зафиксировать фактическое поведение публичного API версии 0.1.0 (решение СЛАУ,
матричные операции, Холецкий, обусловленность, собственные значения, квадратура Гаусса–Лежандра,
чистые функции `Measured`/`ForwardError`/`orders`), чтобы при переработке библиотеки ловить регрессии,
а не только «тесты на свойства». Входы детерминированы (`GoldenInputs`, `java.util.Random` с фиксированными seed).

Формат: JSON; каждое `Double` записано hex-строкой из 16 символов (`toRawBits()`), т.е. без потери точности.
`generatedWith` хранит версию, имя бэкенда и дату генерации. Чтение/запись — `GoldenIo` (без внешних зависимостей).

Перегенерировать: `./gradlew regenerateGolden` (тег `golden-generate`, в обычный `test`/`fastTest` не входит).
Делать это только осознанно — при намеренном изменении поведения, с описанием причины в коммите.

Допуски проверок (`Golden*Test`, тег `fast`): `1e-12` относительно по норме `‖got−exp‖∞ / max(‖exp‖∞, 1)`;
`1e-6` для матриц Гильберта (`hilbert-*` в `solve.json`, `conditioning.json`) — cond ~1e10 при n=8, и разные
корректные реализации LU расходятся именно на этом уровне; `pure.json` сравнивается побитово (`assertBits`), `null == null`.

Поле `inversionResidual` сравнивается по порядку величины (либо оба значения ниже уровня шума `100·ε·condInf`) и по признаку достоверности `isReliable`, а не относительно: на плохо обусловленных матрицах это шум округления, который зависит от реализации LAPACK и порядка операций.

Эталон `orders` для входа с бесконечностью обновлён в 1.0.0: бесконечная погрешность даёт `NaN`, как и нулевая.
