# numerical-core-openblas

## Назначение

Модуль подключает к `numerical-core` упакованную реализацию BLAS/LAPACK — OpenBLAS.
Он нужен на машинах, где системной BLAS/LAPACK нет: на рабочих станциях и ноутбуках,
в контейнерах с минимальным образом. На вычислительных кластерах с установленными
MKL, AOCL или OpenBLAS модуль не нужен — библиотека возьмёт системную реализацию сама.

## Подключение

```kotlin
implementation("io.github.egorkakulikov:numerical-core-openblas:<версия>")
```

Зависимость на `numerical-core` подтягивается автоматически.

## Использование

Вызовите `OpenBlas.install()` до первого обращения к библиотеке — путь к нативной
реализации читается один раз при инициализации:

```kotlin
fun main() {
    OpenBlas.install()
    println(Backends.describe())
}
```

Альтернатива без этого модуля — задать системные свойства
`dev.ludovic.netlib.blas.nativeLibPath` и `dev.ludovic.netlib.lapack.nativeLibPath`
вручную, указав полный путь к файлу библиотеки.

## Потоки и стек

По умолчанию OpenBLAS использует `min(число ядер, 4)` потоков: на процессорах с
разнородными ядрами большее число потоков замедляет разложения. Число потоков задаётся
параметром `OpenBlas.install(threads = …)`.

При `threads > 1` вызывающему потоку нужен стек не менее 4 МБ: запускайте JVM с `-Xss4m`
либо решайте большие системы в потоке с явно заданным стеком —
`Thread(null, r, "lapack", 8L shl 20)`. Иначе внутри OpenBLAS возможен аварийный
останов JVM.

## Размер и платформы

Зависимость добавляет 13–48 МБ на платформу. Поддерживаются linux-x86_64, linux-arm64,
macosx-arm64, macosx-x86_64, windows-x86_64.

## Проверка

`Backends.describe()` после `OpenBlas.install()` должен показывать нативную реализацию.
