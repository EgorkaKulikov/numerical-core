# Производительность

## Целевой режим

Библиотека рассчитана на плотные матрицы размера `10²…10⁴`. В этом диапазоне время
определяется реализацией BLAS/LAPACK: `solve`, `matMat`, `cholesky`, `symmetricEigenvalues`
стоят `O(n³)`, `matVec`, `conditionEstimate` (после разложения) — `O(n²)`. Задача библиотеки —
не добавлять к этому собственных накладных расходов и не мешать нативной библиотеке
использовать все ядра.

## Путь данных

`DenseMatrix` хранит элементы в столбцовом порядке (`data: DoubleArray`, элемент `(i, j)` по
индексу `i + j·rows`) — именно так ожидают данные BLAS и LAPACK. Матрица передаётся в
нативную библиотеку без копирования и без транспонирования; результат также записывается
напрямую в `DoubleArray`. Конструктор `DenseMatrix.fromColumnMajor` принимает готовый массив
без копии, `fromRows` и `build` создают новый массив один раз.

Перегрузки методов `LinearAlgebra` и `Conditioning`, принимающие `Array<DoubleArray>`,
копируют данные в столбцовый порядок при каждом вызове. Для повторяющихся вычислений с
одной матрицей следует один раз построить `DenseMatrix` и передавать её.

## Многопоточность

Внутри операций линейной алгебры библиотека потоков не создаёт: параллелизм даёт нативная
реализация BLAS/LAPACK и управляется её переменными окружения — `OMP_NUM_THREADS` и
`MKL_NUM_THREADS` для Intel MKL, `OPENBLAS_NUM_THREADS` для OpenBLAS,
`VECLIB_MAXIMUM_THREADS` для Apple Accelerate. На вычислительном узле кластера эти
переменные обычно выставляет система пакетной обработки заданий.

Единственное место, где библиотека сама распределяет работу по потокам, — `ParallelAssembly`:
сборка матрицы по строкам выполняется через общий пул `ForkJoinPool`, степень параллелизма
задаётся `NumericsContext.parallelism`, а `parallel = false` даёт последовательное
выполнение для отладки и воспроизводимости.

Все публичные методы потокобезопасны: разные потоки могут одновременно решать разные
системы через одну реализацию линейной алгебры.

## Измерения

Машина: Apple M1 Pro, 8 ядер, macOS, JDK 21; системная библиотека Apple Accelerate.
Время в миллисекундах, медиана из 5 замеров после 3 прогревов (`conditionInf` и
`symmetricEigenvalues` — медиана из 3). Входы детерминированы (`java.util.Random(1000 + n)`,
диагонально доминирующие матрицы). Разброс между запусками — до ±30 %, поэтому значимы
порядки величин и отношения, а не вторые знаки. Полная таблица версии 0.1.0 — в
`core/benchmark/BASELINE-0.1.0.md`.

| Операция | n | 0.1.0 | 1.0.0 |
|---|---:|---:|---:|
| `solve` | 256 | 2.05 | 0.99 |
| `solve` | 1024 | 37.66 | 11.50 |
| `solve` | 2048 | 179.82 | 55.84 |
| `matMat` | 256 | 11.73 | 0.18 |
| `matMat` | 1024 | 37.26 | 5.98 |
| `matMat` | 2048 | 210.71 | 40.82 |
| `matVec` | 1024 | 3.72 | 0.13 |
| `matTransVec` | 1024 | 7.43 | 0.15 |
| `atWa` | 1024 | 42.68 | 6.11 |
| `conditionInf` | 256 | 294.35 | 1.45 |
| `conditionInf` | 1024 | не измерялось | 24.43 |
| `conditionEstimate` | 1024 | отсутствовало | 8.44 |
| `symmetricEigenvalues` | 256 | 90.21 | 3.05 |
| `symmetricEigenvalues` | 1024 | не измерялось | 155.43 |

Версия 0.1.0 копировала данные при каждом обращении к нативной библиотеке, вычисляла
`conditionInf` и `symmetricEigenvalues` собственным кодом на JVM и не имела оценки
обусловленности по LU-разложению. В 1.0.0 все операции `O(n³)` выполняет LAPACK, данные
передаются без копирования, `conditionEstimate` даёт обусловленность за `O(n²)` после
факторизации.

## Переносимая реализация на Java

При отсутствии нативной библиотеки используется реализация BLAS/LAPACK на Java из netlib
(F2J). Она однопоточна и медленнее в 10–20 раз: `solve` при `n = 1024` занимает около
140 мс против 10–12 мс, `matMat` — около 200 мс против 6 мс. Библиотека сообщает о переходе
на неё предупреждением; `Backends.describe()` показывает, какая реализация выбрана.
Режим задаётся системным свойством `-Dnumerics.backend=native|java|auto`.

## Модуль OpenBLAS

`numerical-core-openblas` поставляет OpenBLAS через JavaCPP Presets для систем без
собственной библиотеки. По умолчанию `OpenBlas.install()` задаёт `min(число ядер, 4)`
потоков: на процессорах с разнородными ядрами большее число потоков замедляет разложения.
При `threads > 1` вызывающему потоку нужен стек не менее 4 МБ — запускайте JVM с `-Xss4m`
либо решайте большие системы в потоке с явно заданным размером стека; иначе возможен
аварийный останов JVM внутри OpenBLAS. Подробности — в `openblas/README.md`.

## Как повторить измерения

    ./gradlew :numerical-core:benchmark -Pbench.args="256 1024 2048"

Исходный код измерений — `core/src/benchmark/kotlin/numerics/bench/Bench.kt` (отдельный
набор исходников, в артефакт не входит). Для сравнения реализаций добавьте
`-Dnumerics.backend=java` или `-Dnumerics.backend=native`.
