# Точность и достоверность результатов

Документ описывает, какие величины библиотека вычисляет для контроля точности, что они
означают математически и какие гарантии даёт каждый публичный метод. Все числовые
примеры взяты из тестов библиотеки.

## Обратная ошибка

Для системы `Ax = b` и вычисленного решения `x` библиотека вычисляет относительную
обратную ошибку в бесконечной норме:

    ω = ‖Ax − b‖∞ / max(‖A‖∞ ‖x‖∞, ‖b‖∞).

По теореме Ригала–Гаше `ω` — наименьшее число, при котором `x` является точным решением
возмущённой системы `(A + ΔA) x = b + Δb` с `‖ΔA‖∞ ≤ ω ‖A‖∞` и `‖Δb‖∞ ≤ ω ‖b‖∞`. Иначе
говоря, `ω` показывает, насколько нужно изменить исходные данные, чтобы найденное решение
стало точным.

LU-разложение с частичным выбором ведущего элемента обратно устойчиво: для корректной
реализации `ω` имеет порядок `n·ε`, где `ε ≈ 1.1·10⁻¹⁶` — единичное округление двойной
точности. Поэтому проверки `ω` достаточно, чтобы обнаружить любую неисправность решателя —
вырожденность матрицы, нечисловые данные, ошибку реализации LAPACK — независимо от того,
какая именно библиотека выполняла разложение. Величина `ω` вычисляется за `O(n²)` и не
требует знания точного решения.

`LinearAlgebra.solve` вычисляет `ω` после каждого решения и отвергает результат
исключением, если `ω` превышает `SINGULARITY_RELATIVE_TOLERANCE = 1e-10` или содержит
нечисловые значения. Нечисловой вход (`NaN`, `±Inf`) отвергается до вызова LAPACK.

### Обоснование порога 1e-10

Для матриц размера до `10⁴` ожидаемая обратная ошибка корректного решения не превышает
`n·ε ≈ 10⁻¹²`, а на практике оказывается на два–три порядка меньше. Порог `10⁻¹⁰` оставляет
запас в два порядка сверх наихудшей оценки и при этом на много порядков ниже значений,
которые возникают при численной вырожденности: там `ω` обычно лежит в диапазоне
`10⁻³…1`, поскольку разложение делит на ведущие элементы уровня шума. Порог не зависит от
обусловленности матрицы: плохо обусловленная, но невырожденная система решается с малой
`ω` — неточность в таком случае проявляется в прямой ошибке, а не в невязке.

## Прямая ошибка и режимы `ForwardError`

Прямая ошибка — расстояние до точного решения `x*`. Из обратной ошибки она оценивается
в первом порядке как

    ‖x − x*‖∞ / ‖x*‖∞ ≤ cond∞(A) · ω,   cond∞(A) = ‖A‖∞ ‖A⁻¹‖∞.

`LinearAlgebra.solveDiagnosed` возвращает решение вместе со значением закрытого типа
`ForwardError`, у которого три варианта:

| Вариант | Условие | Смысл |
|---|---|---|
| `Bounded(backwardError, cond, relativeBound)` | оценка `cond` достоверна и `cond · ω < 1` | Относительная ошибка не превышает `relativeBound = cond · ω`; `survivingDigitsOrNull()` возвращает число сохранившихся десятичных знаков. |
| `NoFiniteBound(backwardError)` | оценка `cond` достоверна, но `cond · ω ≥ 1` | Граница не несёт информации: система численно вырождена на уровне точности решения. |
| `Unreliable(backwardError, condition)` | оценка `cond` сама недостоверна | О прямой ошибке ничего сказать нельзя; в `condition` — данные, по которым принято решение. |

Недостоверная оценка не возвращается как число: `relativeBoundOrNull()` даёт `null`
для двух последних вариантов, и код, которому нужна граница, обязан явно обработать её
отсутствие.

```kotlin
val d = LinearAlgebra.solveDiagnosed(a, b)
when (val e = d.forwardError) {
    is ForwardError.Bounded       -> println("ошибка ≤ ${e.relativeBound}")
    is ForwardError.NoFiniteBound -> println("численно вырожденная система, ω = ${e.backwardError}")
    is ForwardError.Unreliable    -> println("обусловленность не определена достоверно")
}
```

## Три способа получить число обусловленности

`ConditionSource` выбирает, как вычисляется `cond` для оценки прямой ошибки.

**`INVERSION`** — `Conditioning.conditionInf`. Вычисляется точное `‖A‖∞ ‖A⁻¹‖∞` через
явное обращение (LAPACK `dgetrf` + `dgetri`), `O(n³)` операций и `n²` дополнительной
памяти. Признак достоверности — невязка обращения `‖A·A⁻¹ − I‖∞`: если она превышает
`INVERSION_RESIDUAL_TOLERANCE = 1e-8`, вычисленная обратная матрица сама неточна и
`ConditionEstimate.isReliable` равен `false`. Невязка обращения растёт как `cond · ε`,
поэтому при `cond ≳ 10⁸` источник `INVERSION` перестаёт давать достоверные значения — и
сообщает об этом, а не возвращает случайное число.

**`ESTIMATE`** — `Conditioning.conditionEstimate`. Оценка LAPACK `dgecon` в норме-1 по
уже готовому LU-разложению: `O(n²)` операций после факторизации, без дополнительной
матрицы. Это оценка снизу для `cond₁(A)`; она отличается от точного значения не более чем
в несколько раз (для алгоритма Хагера–Хайема типично не более чем втрое). Для симметричных
матриц `cond₁ = cond∞`; в общем случае нормы различаются на множитель, зависящий от `n`,
поэтому граница `cond · ω` с этим источником носит оценочный характер.

**`SYMMETRIC_SPECTRUM`** — `Conditioning.conditionSymmetric`. Для симметричной матрицы
`cond₂ = |λ|max / |λ|min` по спектру, вычисленному LAPACK `dsyev`. Несимметричная матрица
(по `maxAsymmetry`) отвергается исключением.

### Пример: матрица Гильберта 8×8

`cond∞ ≈ 1.5·10¹⁰`. Две корректные реализации LAPACK (Apple Accelerate и переносимая
реализация на Java) дают решения `Hx = b`, различающиеся на `≈1.6·10⁻⁸`, при том что на
обычных матрицах расхождение не превышает `2·10⁻¹⁶`. Это ожидаемо и укладывается в границу
`cond · ω ≈ 1.5·10¹⁰ · 10⁻¹⁶`. Невязка обращения на той же матрице составляет
`10⁻⁷…10⁻⁶` в зависимости от реализации — выше порога `10⁻⁸`, поэтому источник
`INVERSION` возвращает `Unreliable`, а `ESTIMATE` — достоверную оценку порядка `10¹⁰`.

## Измеренные величины и порог шума

Для величин, получаемых суммированием (нормы разностей, ошибки на сетках), библиотека
вводит тип `Measured` и функцию `measured(value, threshold = MACHINE_NOISE_THRESHOLD)`:

- `Reliable(value)` — `|value| ≥ threshold`, величина отражает измеряемое явление;
- `AtNoiseLevel(value, threshold)` — `|value| < threshold`, величина неотличима от
  накопленной ошибки округления.

Граница включена: значение, равное порогу, считается достоверным. Порог
`MACHINE_NOISE_THRESHOLD = 1e-13` выбран так: суммирование `10³` слагаемых порядка единицы
накапливает ошибку до `10³ · ε ≈ 10⁻¹³`; для более длинных сумм или иного масштаба данных
порог задаётся явно. Функции `reliableOrders` и `reliableConstCh` вычисляют наблюдаемый
порядок сходимости `log₂(e_h / e_{h/2})` и константу `C = e_h / h^p` только по достоверным
измерениям, возвращая `null` там, где хотя бы одна ошибка лежит на уровне шума — иначе
логарифм отношения двух шумовых величин выглядел бы как осмысленный порядок.

## Спектр симметричных матриц

`Conditioning.symmetricEigenvalues` возвращает собственные значения по возрастанию,
вычисленные LAPACK `dsyev`. Реализации BLAS/LAPACK с внутренней многопоточностью (в
частности, Apple Accelerate) при параллельной нагрузке воспроизводят собственные значения
с разбросом порядка `10⁻¹⁴`; это свойство системной библиотеки, и тесты библиотеки
сравнивают спектры с соответствующим допуском.

## Сводка гарантий

| Метод | Что проверяется | Что происходит при нарушении |
|---|---|---|
| `LinearAlgebra.solve` | `ω ≤ 1e-10`, отсутствие `NaN`/`Inf` во входе и выходе | `IllegalStateException` |
| `LinearAlgebra.solveDiagnosed` | то же, плюс оценка прямой ошибки | `ForwardError.NoFiniteBound` или `Unreliable` вместо числа |
| `LinearAlgebra.cholesky` | симметричность (`maxAsymmetry`), положительная определённость | `IllegalArgumentException`; `null` для не положительно определённой |
| `Conditioning.conditionInf` | невязка обращения `≤ 1e-8` | `ConditionEstimate.isReliable = false`, `valueOrNull() = null` |
| `Conditioning.conditionEstimate` | вырожденность LU | `isReliable = false` при вырожденной матрице |
| `Conditioning.symmetricEigenvalues` | симметричность входа | `IllegalArgumentException` |
| `GaussLegendre.integrate` | не менее двух точек разбиения, монотонность | `IllegalArgumentException` |
| `measured`, `reliableOrders`, `reliableConstCh` | `|value| ≥ threshold` | `AtNoiseLevel` / `null` |

Все проверки выполняются одинаково для любой реализации BLAS/LAPACK: системной,
упакованной OpenBLAS и переносимой на Java.
