# Производительность

## Целевой режим

Библиотека рассчитана на плотные матрицы размера `10²…10⁴`. В этом диапазоне время работы
определяется реализацией BLAS/LAPACK: операции `solve`, `matMat`, `cholesky`,
`symmetricEigenvalues` имеют сложность `O(n³)`, операции `matVec` и `conditionEstimate`
(после разложения) — `O(n²)`. Библиотека не добавляет к этому собственных накладных расходов
и не ограничивает параллелизм системной реализации.

## Путь данных

`DenseMatrix` хранит элементы в столбцовом порядке (`data: DoubleArray`, элемент `(i, j)`
расположен по индексу `i + j·rows`), то есть в порядке, ожидаемом BLAS и LAPACK. Матрица
передаётся в реализацию BLAS/LAPACK без переупорядочения и транспонирования. Умножения (`matVec`,
`matMat`) и нормы работают с массивом матрицы непосредственно. В операциях, где LAPACK
перезаписывает входные данные (`solve`, LU-разложение, разложение Холецкого, спектр
симметричной матрицы), создаётся одна копия размера матрицы, поэтому исходные матрицы не
изменяются. Результат записывается непосредственно в новый `DoubleArray`. Конструктор
`DenseMatrix.fromColumnMajor` принимает готовый массив без копирования; `fromRows` и `build`
создают новый массив один раз.

Перегрузки методов `LinearAlgebra` и `Conditioning`, принимающие `Array<DoubleArray>`,
копируют данные в столбцовый порядок при каждом вызове. При повторяющихся вычислениях с
одной матрицей следует один раз построить `DenseMatrix` и передавать его.

## Многопоточность

Внутри операций линейной алгебры библиотека потоков не создаёт: параллелизм обеспечивается
реализацией BLAS/LAPACK и управляется её переменными окружения — `OMP_NUM_THREADS` и
`MKL_NUM_THREADS` для Intel MKL, `OPENBLAS_NUM_THREADS` для OpenBLAS,
`VECLIB_MAXIMUM_THREADS` для Apple Accelerate. На вычислительном узле кластера эти
переменные, как правило, задаются системой пакетной обработки заданий.

Единственный компонент, в котором библиотека сама распределяет работу по потокам, —
`ParallelAssembly`: сборка матрицы по строкам выполняется через общий пул `ForkJoinPool`,
степень параллелизма задаётся параметром `NumericsContext.parallelism`, а значение
`parallel = false` включает последовательное выполнение для отладки и воспроизводимости.

Все публичные методы потокобезопасны: разные потоки могут одновременно решать разные
системы через один экземпляр реализации линейной алгебры.

## Измерения

Машина: Apple M1 Pro, 8 ядер, macOS, JDK 21; системная реализация — Apple Accelerate.
Время приведено в миллисекундах как медиана из 5 замеров после 3 прогревов (для
`conditionInf` и `symmetricEigenvalues` — медиана из 3). Входные данные детерминированы
(`java.util.Random(1000 + n)`, диагонально доминирующие матрицы). Разброс между запусками
достигает ±30 %, поэтому значимы порядки величин и отношения, а не вторые знаки. Полная
таблица версии 0.1.0 приведена в `core/benchmark/BASELINE-0.1.0.md`.

| Операция | n | 0.1.0 | 1.0.0 |
|---|---:|---:|---:|
| `solve` | 256 | 2.05 | 0.99 |
| `solve` | 1024 | 37.66 | 11.50 |
| `solve` | 2048 | 179.82 | 55.84 |
| `matMat` | 256 | 11.73 | 0.18 |
| `matMat` | 1024 | 37.26 | 5.98 |
| `matMat` | 2048 | 210.71 | 40.82 |
| `matVec` | 1024 | 3.72 | 0.13 |
| `matTransVec` | 1024 | 7.43 | 0.15 |
| `atWa` | 1024 | 42.68 | 6.11 |
| `conditionInf` | 256 | 294.35 | 1.45 |
| `conditionInf` | 1024 | не измерялось | 24.43 |
| `conditionEstimate` | 1024 | отсутствовало | 8.44 |
| `symmetricEigenvalues` | 256 | 90.21 | 3.05 |
| `symmetricEigenvalues` | 1024 | не измерялось | 155.43 |

В версии 0.1.0 данные преобразовывались в промежуточный формат при каждом вызове,
`conditionInf` и `symmetricEigenvalues` вычислялись кодом на JVM, оценка обусловленности
по LU-разложению отсутствовала. В версии 1.0.0 матрица хранится в формате BLAS/LAPACK и
передаётся без переупорядочения, все операции сложности `O(n³)` выполняются LAPACK,
`conditionEstimate` вычисляет оценку обусловленности за `O(n²)` после разложения.

## Переносимая реализация на Java

При отсутствии машинно-зависимой реализации используется реализация BLAS/LAPACK на Java из netlib
(F2J). Она однопоточна и медленнее в 10–20 раз: `solve` при `n = 1024` занимает около
140 мс против 10–12 мс, `matMat` — около 200 мс против 6 мс. О переходе на переносимую
реализацию библиотека сообщает предупреждением; метод `Backends.describe()` возвращает
описание выбранной реализации. Режим задаётся системным свойством
`-Dnumerics.backend=native|java|auto`.

## Модуль OpenBLAS

Модуль `numerical-core-openblas` поставляет OpenBLAS через JavaCPP Presets для систем без
собственной реализации BLAS/LAPACK. По умолчанию `OpenBlas.install()` задаёт `min(число ядер, 4)`
потоков: на процессорах с разнородными ядрами большее число потоков замедляет разложения.
При `threads > 1` вызывающему потоку требуется стек не менее 4 МБ: JVM запускается с
параметром `-Xss4m`, либо решение больших систем выполняется в потоке с явно заданным
размером стека; в противном случае возможен аварийный останов JVM внутри OpenBLAS.
Подробности приведены в `openblas/README.md`.

## Воспроизведение измерений

    ./gradlew :numerical-core:benchmark -Pbench.args="256 1024 2048"

Исходный код измерений находится в `core/src/benchmark/kotlin/numerics/bench/Bench.kt`
(отдельный набор исходников, в артефакт не входит). Для сравнения реализаций к команде
добавляется параметр `-Dnumerics.backend=java` или `-Dnumerics.backend=native`.
