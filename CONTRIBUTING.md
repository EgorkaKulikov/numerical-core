# Правила изменения numerical-core

numerical-core — библиотека численных примитивов для плотных вычислений на Kotlin/JVM с
контролем достоверности результатов. Ниже — правила, которым следуют все изменения кода
и документации.

## Язык

Документация, KDoc, комментарии и сообщения коммитов — на русском языке. Идентификаторы в
коде — на английском. Стиль текста описательный и спокойный: без выделения заглавными
буквами, без жаргона, без ссылок на внешние проекты и историю версий.

## Публичный API

- Включён `explicitApi()`: всё новое объявляется `internal`. Публичным элемент становится
  только вместе с KDoc и тестом, покрывающим его контракт.
- Недостоверное значение не возвращается как число: используются `ForwardError`,
  `Measured`, `ConditionEstimate.isReliable` или `null`.
- Нечисловой вход (`NaN`, `±Inf`) в `solve`, `cholesky` и других методах линейной алгебры
  отвергается исключением до обращения к BLAS/LAPACK.
- Поведение метода — проверки, исключения, форма результата — не зависит от реализации
  BLAS/LAPACK.

## Численные методы

- Каждый метод сопровождается тестом на точность (сравнение с независимым оракулом или с
  аналитическим ответом) и записью в `docs/ИСТОЧНИКИ.md` с указанием источника формул.
- Пороги (`SINGULARITY_RELATIVE_TOLERANCE`, `INVERSION_RESIDUAL_TOLERANCE`,
  `MACHINE_NOISE_THRESHOLD`) меняются только с обоснованием в `docs/ТОЧНОСТЬ.md`.
- Изменение формулы проверяется golden-тестами и свойствами jqwik на обеих реализациях
  (`-Dnumerics.backend=java` и `native`). Эталоны обновляются командой
  `./gradlew :numerical-core:regenerateGolden` только осознанно, с записью причины в
  `core/src/test/resources/golden/README.md`.

## Команды

    ./gradlew build                                              # тесты, покрытие Kover, оба модуля
    ./gradlew :numerical-core:test -Dnumerics.backend=java       # переносимая реализация
    ./gradlew :numerical-core:test -Dnumerics.backend=native     # системная библиотека
    ./gradlew :numerical-core:benchmark -Pbench.args="256 1024"  # измерения производительности
    ./gradlew :numerical-core:dokkaHtml                          # документация API

Задача `check` включает проверку порога покрытия Kover; изменение, снижающее покрытие ниже
порога, не проходит сборку. Все команды работают с флагом `--offline`.

## Документация

После изменения API обновляются `README.md` (таблица состава, пример) и соответствующий
документ в `docs/`. Числа в `docs/ПРОИЗВОДИТЕЛЬНОСТЬ.md` снимаются командой `benchmark` с
указанием машины и реализации BLAS/LAPACK.

## Коммиты

Сообщения на русском языке с префиксом области: `api:`, `algo:`, `test:`, `docs:`, `build:`.
Одно изменение — один коммит; сообщение описывает, что изменилось и зачем.
